# Todoタスク管理アプリ README

## 1. アプリ概要

このアプリは、ユーザー登録・ログイン後にタスクを登録・一覧表示・カテゴリ別表示するためのWebアプリケーションです。

現在の実装では、ユーザー情報、カテゴリ情報、タスク情報をPostgreSQLで管理し、ログイン後にタスク一覧画面を表示する構成になっています。

ただし、現状コードにはログイン制御、カテゴリ検索URL、タスク更新・削除処理、ユーザーIDの紐付け、HTML構造などに未完成の箇所があります。  
まずは「ログインユーザーごとのタスク登録・一覧表示」が正しく動く状態にすることが最優先です。

---

## 2. 主な機能

| No | 機能 | 現在の状態 | 内容 |
|---|---|---|---|
| 1 | ログイン | 実装済み | ユーザー名とパスワードでログインする |

## 7. データベース設計

### users テーブル

ユーザー情報を管理するテーブルです。

```sql
CREATE TABLE users
(
   user_id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
   name VARCHAR(20),
   password TEXT
);
```

| カラム名 | 型 | 制約 | 内容 |
|---|---|---|---|
| user_id | INTEGER | PRIMARY KEY / 自動採番 | ユーザーID |
| name | VARCHAR(20) | なし | ユーザー名 |
| password | TEXT | なし | パスワード |

---

### categories テーブル

タスクカテゴリを管理するテーブルです。

```sql
CREATE TABLE categories
(
   category_id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
   category_name VARCHAR(20)
);
```

| カラム名 | 型 | 制約 | 内容 |
|---|---|---|---|
| category_id | INTEGER | PRIMARY KEY / 自動採番 | カテゴリID |
| category_name | VARCHAR(20) | なし | カテゴリ名 |

---

### tasks テーブル

タスク情報を管理するテーブルです。

```sql
CREATE TABLE tasks
(
   task_id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
   user_id INTEGER,
   category_id INTEGER,
   title VARCHAR(255),
   closing_date DATE,
   progress INTEGER,
   memo TEXT,
   time INTEGER,
   date DATE
);
```

| カラム名 | 型 | 制約 | 内容 |
|---|---|---|---|
| task_id | INTEGER | PRIMARY KEY / 自動採番 | タスクID |
| user_id | INTEGER | なし | ユーザーID |
| category_id | INTEGER | なし | カテゴリID |
| title | VARCHAR(255) | なし | タスクタイトル |
| closing_date | DATE | なし | 期限 |
| progress | INTEGER | なし | 進捗状況 |
| memo | TEXT | なし | メモ |
| time | INTEGER | なし | 予定所要時間 |
| date | DATE | なし | 開始日 |

### DB設計上の注意点

現在の `tasks` テーブルには `user_id` と `category_id` がありますが、外部キー制約が設定されていません。

安定した設計にするなら、以下のように外部キーを設定する方が望ましいです。

```sql
FOREIGN KEY (user_id) REFERENCES users(user_id),
FOREIGN KEY (category_id) REFERENCES categories(category_id)
```

## 12. 処理の流れ

### 12-1. ログイン処理

```text
ログイン画面を表示
  ↓
ユーザー名とパスワードを入力
  ↓
UserRepositoryでユーザー検索
  ↓
一致するユーザーが存在するか確認
  ↓
存在する場合、Accountにid、name、passwordを保存
  ↓
タスク一覧画面へリダイレクト
```

---

### 12-2. 新規ユーザー登録処理

```text
新規ユーザー登録画面を表示
  ↓
ユーザー名、パスワード、確認用パスワードを入力
  ↓
パスワードと確認用パスワードが一致するか確認
  ↓
一致していればusersテーブルへ保存
  ↓
ログイン画面へ戻る
```

---

### 12-3. タスク一覧表示処理

```text
/task へアクセス
  ↓
カテゴリ一覧を取得
  ↓
categoryId がない場合は全タスクを取得
  ↓
categoryId がある場合はカテゴリIDでタスクを検索
  ↓
task.htmlへ categories と tasks を渡す
  ↓
タスク一覧を表示
```

現在は、ログイン中ユーザーに関係なく全タスクを表示する構成になっています。

---

### 12-4. タスク新規登録処理

```text
タスク新規作成画面を表示
  ↓
カテゴリ、タイトル、開始日、期限、予定時間、メモを入力
  ↓
Taskオブジェクトを作成
  ↓
progress に 0 を設定
  ↓
tasksテーブルへ保存
  ↓
タスク一覧画面へ戻る
```

現在は、ログイン中ユーザーIDを `tasks.user_id` に保存していません。

# 15. 現在の問題点

## 15-1. 未ログインでも `/task` にアクセスできる

現在、`TaskController.java` の `/task` ではログイン確認をしていません。

そのため、未ログイン状態でも直接以下にアクセスできる可能性があります。

```text
http://localhost:8080/task
```

### 対応方針

`TaskController` の各処理の先頭に以下を追加します。

```java
if (account.getId() == null) {
    return "redirect:/login";
}
```

---

## 15-2. タスク登録時にログインユーザーIDを保存していない

`TaskController.java` の登録処理では、以下のように `Task` を作成しています。

```java
Task task = new Task(categoryId, title, date, closingDate, time, memo);
task.setProgress(0);
taskRepository.save(task);
```

この処理では、`user_id` にログイン中ユーザーのIDが入りません。

そのため、どのユーザーのタスクなのか判別できません。

### 対応方針

登録時に以下を追加します。

```java
task.setUserId(account.getId());
```

---

## 15-3. タスク一覧が全ユーザー共通になっている

現在の一覧取得は以下です。

```java
if (categoryId == null) {
    taskList = taskRepository.findAll();
} else {
    taskList = taskRepository.findByCategoryId(categoryId);
}
```

このままだと、全ユーザーのタスクが表示されます。

### 対応方針

ログインユーザーIDで絞り込みます。

```java
if (categoryId == null) {
    taskList = taskRepository.findByUserId(account.getId());
} else {
    taskList = taskRepository.findByUserIdAndCategoryId(account.getId(), categoryId);
}
```

そのため、`TaskRepository.java` に以下を追加します。

```java
List<Task> findByUserId(Integer userId);

List<Task> findByUserIdAndCategoryId(Integer userId, Integer categoryId);
```

---

## 15-4. カテゴリ絞り込みのHTMLとControllerが一致していない

`TaskController.java` は `/task?categoryId=1` のようなクエリパラメータを想定しています。

しかし、`task.html` では以下のように存在しないURLへ遷移しようとしています。

```html
onchange="location.href='http://localhost:8080/task/all'"
onchange="location.href='http://localhost:8080/task/everydayLife'"
onchange="location.href='http://localhost:8080/task/work'"
```

Controllerには以下のURLがありません。

```text
/task/all
/task/everydayLife
/task/work
```

### 対応方針

カテゴリIDをクエリパラメータとして送ります。

```html
<a href="/task">全て</a>
<a href="/task?categoryId=2">日常</a>
<a href="/task?categoryId=1">仕事</a>
```

またはThymeleafで以下のようにカテゴリ一覧から動的に作ります。

```html
<a th:href="@{/task(categoryId=${category.categoryId})}" th:text="${category.categoryName}"></a>
```

## 15-5. タスク更新処理が未完成

`TaskController.java` に更新処理のコメントアウトがありますが、現在は動作していません。

また、`task.html` の更新フォームも以下のようになっており、実際のタスクIDを送れていません。

<form action="/tasks/{id}/edit" method="post">

```text
GET  /tasks/{id}/edit

```

```html
<a th:href="@{/tasks/{id}/edit(id=${task.taskId})}">更新</a>
```

## 15-6. タスク削除処理が未実装

`task.html` には削除ボタンがあります。

```html
<form action="/tasks/{id}/delete" method="post">
    <button>削除</button>
</form>
```

しかし、`TaskController.java` に以下の処理がありません。

```text
POST /tasks/{id}/delete
```

### 対応方針

Controllerに削除処理を追加します。

```java
@PostMapping("/tasks/{id}/delete")
public String delete(@PathVariable("id") Integer id) {
    taskRepository.deleteById(id);
    return "redirect:/task";
}
```

ただし、他ユーザーのタスクを削除できないように、ログインユーザーIDとの一致確認も追加した方が安全です。

## 15-7. `task.html` のHTML構造が崩れている

`task.html` では、`table` の中に `form` が不自然に配置されています。

また、`th:each` の外側に更新・削除フォームがあるため、各タスクごとの更新・削除になっていません。

### 対応方針

`th:each` の1行内に、更新リンクと削除フォームを置きます。

```html
<tr th:each="task : ${tasks}">
    <td th:text="${task.title}"></td>
    <td th:text="${task.progress}"></td>
    <td th:text="${task.date}"></td>
    <td th:text="${task.closingDate}"></td>
    <td th:text="${task.memo}"></td>
    <td>
        <a th:href="@{/tasks/{id}/edit(id=${task.taskId})}">更新</a>
        <form th:action="@{/tasks/{id}/delete(id=${task.taskId})}" method="post">
            <button>削除</button>
        </form>
    </td>
</tr>
```

## 15-10. 新規ユーザー登録時にエラー表示がない

現在、新規ユーザー登録時にパスワードと確認用パスワードが一致しない場合、何も登録せずにログイン画面へ戻ります。

ユーザーから見ると、何が起きたかわかりません。

### 対応方針

以下の入力チェックを追加します。

- 名前が空ならエラー
- パスワードが空ならエラー
- 確認用パスワードが空ならエラー
- パスワードと確認用パスワードが一致しなければエラー
- 同じユーザー名が既に存在する場合はエラー

`User.java` には `getId()` はありますが、`setId()` がありません。

通常、新規登録では自動採番なので不要ですが、編集やテストで必要になる場合があります。

必須ではありませんが、Entityとしては追加しておくと扱いやすくなります。

# 20. 最終まとめ

このアプリは、ユーザー登録・ログイン後にタスクを管理するTodoアプリです。

現在、ログイン、新規ユーザー登録、タスク一覧表示、タスク新規登録の基本構成は作られています。

一方で、タスク登録時にログインユーザーIDを保存していないため、ユーザーごとのタスク管理ができていません。さらに、一覧表示も全ユーザー共通になっており、ログイン制アプリとしては未完成です。

まずは、`TaskController.java` にログイン確認を追加し、タスク登録時に `task.setUserId(account.getId())` を行います。

次に、`TaskRepository.java` に `findByUserId` と `findByUserIdAndCategoryId` を追加し、一覧表示をログインユーザーのタスクだけに絞り込みます。

その後、カテゴリ絞り込みURL、ログアウトリンク、タスク削除、タスク更新、HTML構造を順番に修正することで、マスト機能に近づけることができます。
